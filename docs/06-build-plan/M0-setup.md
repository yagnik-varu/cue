# M0 · Setup: tools, accounts, monorepo, skeletons

> Status: Ready · Last updated: 2026-10-15 · Related: [build plan README](README.md), [links](links.md), [tech-stack](../05-system-design/tech-stack.md), [hosting](../05-system-design/hosting-and-distribution.md)
>
> Goal of M0: an empty but **working** monorepo. The API answers on `workers.dev`, the web page loads from the same
> Worker, the Android app runs on your phone, the extension loads in Chrome, and CI is green. No product features yet.
> The owner's machine is **Windows**. Commands are written for PowerShell; use `pnpm`, not `npm`.

### M0-T01 · Install developer tools
- **Depends on:** nothing
- **Read first:** [tech-stack.md §1–2](../05-system-design/tech-stack.md)
- **Goal:** every tool needed for the whole project is installed and working.
- **Steps:**
  1. Install **Node.js LTS** (the current LTS from nodejs.org).
  2. Enable pnpm: `corepack enable`, then `corepack prepare pnpm@latest --activate` (or follow the pnpm install page).
  3. Install **Git for Windows**. Set `git config --global user.name` and `user.email`.
  4. Install **Android Studio**. In the SDK Manager install the latest Android SDK Platform, Build-Tools and Platform-Tools. Use the JDK version the Expo/React Native docs require (Android Studio's bundled JDK is usually fine).
  5. Set the environment variables `ANDROID_HOME` (e.g. `%LOCALAPPDATA%\Android\Sdk`) and add `platform-tools` to `PATH`.
  6. On the phone (Oppo/Vivo/Realme/OnePlus): turn on **Developer options → USB debugging**. On ColorOS also enable **"Disable permission monitoring"** if installs fail.
  7. Install the Cloudflare CLI later per project (`wrangler` is a dev dependency, not global).
- **Commands (checks):** `node -v`, `pnpm -v`, `git --version`, `adb devices` (shows your phone)
- **Done when:** all 4 commands print versions, and `adb devices` lists the phone as `device` (not `unauthorized`).
- **Docs:** [Node.js download](https://nodejs.org/en/download) · [pnpm install](https://pnpm.io/installation) · [Android Studio install](https://developer.android.com/studio/install) · [adb](https://developer.android.com/tools/adb) · [Expo: local app development](https://docs.expo.dev/guides/local-app-development/)
- **Learning note:** `M0-T01-dev-environment.md` (concepts: Node vs pnpm, Android SDK, adb)
- **Watch out:** if `adb devices` shows `unauthorized`, unlock the phone and accept the RSA prompt.

### M0-T04 · Monorepo scaffold (pnpm workspaces + Turborepo + shared config)
- **Depends on:** M0-T03
- **Read first:** [tech-stack.md §1](../05-system-design/tech-stack.md#1-monorepo-layout-d-36)
- **Goal:** the layout from tech-stack §1 exists, with shared TypeScript, ESLint and Prettier config.
- **Steps:**
  1. Root `package.json`: `"private": true`, `"packageManager": "pnpm@<version>"`, and scripts `build`, `dev`, `lint`, `typecheck`, `test`, all running through `turbo run …`.
  2. `pnpm-workspace.yaml` with `packages: ["apps/*", "packages/*"]`.
  3. `turbo.json` with the tasks `build` (dependsOn `^build`, outputs `dist/**`), `dev` (persistent, no cache), `lint`, `typecheck`, `test`.
  4. `packages/config/`: `tsconfig.base.json` (strict, `moduleResolution: "Bundler"`, `target: "ES2022"`), `eslint.config.js` (flat config, TypeScript), `prettier.config.js`.
  5. Create empty folders `apps/` and `packages/` with a `README.md` each explaining what goes there.
- **Commands:** `pnpm add -D -w turbo typescript eslint prettier @eslint/js typescript-eslint` · `pnpm install` · `pnpm turbo run lint`
- **Done when:** `pnpm install` succeeds, and `pnpm lint` / `pnpm typecheck` run (doing nothing yet) without errors.
- **Docs:** [pnpm workspaces](https://pnpm.io/workspaces) · [Turborepo docs](https://turborepo.dev/docs) · [tsconfig reference](https://www.typescriptlang.org/tsconfig/) · [ESLint config files](https://eslint.org/docs/latest/use/configure/configuration-files) · [Prettier install](https://prettier.io/docs/install)
- **Learning note:** `M0-T04-monorepo.md` (concepts: workspaces, task graph and caching, shared tsconfig)
- **Watch out:** keep config minimal. Don't add Babel or Jest at the root.

### M0-T05 · `packages/shared` skeleton + Vitest

- **Read first:** [tech-stack.md §3](../05-system-design/tech-stack.md#3-packagesshared-what-lives-there)

- **Steps:**

  4. Add `zod` as a dependency and `vitest` as a dev dependency. Script: `"test": "vitest run"`.
- **Commands:** `pnpm --filter @cue/shared add zod` · `pnpm --filter @cue/shared add -D vitest` · `pnpm --filter @cue/shared test`
- **Done when:** the test passes, and `pnpm typecheck` passes.
- **Docs:** [Vitest guide](https://vitest.dev/guide/) · [zod](https://zod.dev/)

### M0-T06 · `apps/api`: Hono on Cloudflare Workers + local D1 + first deploy
- **Depends on:** M0-T05
- **Read first:** [architecture.md §1–2](../05-system-design/architecture.md) · [hosting §1](../05-system-design/hosting-and-distribution.md#1-what-runs-where)
- **Goal:** `GET /health` returns `{ ok: true }` locally and on `https://cue-api.<you>.workers.dev`.
- **Steps:**
  1. Scaffold with the Hono Cloudflare Workers template into `apps/api`, or create it by hand: `src/index.ts`, `wrangler.jsonc`, `package.json` (name `@cue/api`).
  2. In `wrangler.jsonc`: `name: "cue-api"`, set `compatibility_date` to today, and enable the `nodejs_compat` flag only if a library needs it (prefer not to).
  3. Create D1 databases: `pnpm wrangler d1 create cue-dev` and `pnpm wrangler d1 create cue-prod`. Add both to `wrangler.jsonc` (dev as the default binding `DB`, prod under `env.production`).
  4. Route `GET /health` → `{ ok: true, version: SHARED_VERSION }` (imports from `@cue/shared` to prove the workspace link works).
  5. Add `@cloudflare/vitest-pool-workers` and one test for `/health`.
  6. Log in: `pnpm wrangler login`. Deploy: `pnpm wrangler deploy --env production`.
- **Commands:** `pnpm --filter @cue/api dev` · `curl http://localhost:8787/health` · `pnpm --filter @cue/api test` · `pnpm --filter @cue/api exec wrangler deploy --env production`
- **Done when:** local and deployed `/health` both return JSON, and the test passes.
- **Docs:** [Hono on Workers](https://hono.dev/docs/getting-started/cloudflare-workers) · [Wrangler install](https://developers.cloudflare.com/workers/wrangler/install-and-update/) · [D1 get started](https://developers.cloudflare.com/d1/get-started/) · [Workers Vitest integration](https://developers.cloudflare.com/workers/testing/vitest-integration/) · [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)
- **Learning note:** `M0-T06-workers-hono.md` (concepts: a Worker vs an Express server, bindings, wrangler, environments)
- **Watch out:** remember the 10 ms CPU limit (D-43) from day one. No heavy libraries.

### M0-T07 · `apps/web`: Vite + React PWA served by the same Worker
- **Depends on:** M0-T06
- **Read first:** [hosting §1](../05-system-design/hosting-and-distribution.md#1-what-runs-where) (D-41)
- **Goal:** the Worker URL `/` shows a "Cue" page, and `/api/*` is the API on the same origin.
- **Steps:**
  1. Scaffold a Vite React TypeScript app in `apps/web` (package `@cue/web`).
  2. Move API routes under the `/api` prefix in `apps/api` (e.g. `/api/health`). Update the test.
  3. In `apps/api/wrangler.jsonc` add `assets: { directory: "../web/dist", not_found_handling: "single-page-application" }` so the Worker serves the built web app and its routes.
  4. Root build: Turborepo builds `@cue/web` before deploying `@cue/api`.
  5. Add `vite-plugin-pwa` with a basic manifest (name "Cue", icons, theme colours). Skip offline caching (D-39).
- **Commands:** `pnpm --filter @cue/web build` · `pnpm --filter @cue/api dev` (open http://localhost:8787) · deploy as in M0-T06
- **Done when:** the deployed URL shows the Cue page, `/api/health` still works, and Chrome offers "Install app".
- **Docs:** [Vite guide](https://vite.dev/guide/) · [Workers static assets](https://developers.cloudflare.com/workers/static-assets/) · [vite-plugin-pwa](https://vite-pwa-org.netlify.app/guide/)
- **Learning note:** `M0-T07-static-assets-pwa.md` (concepts: SPA routing, same-origin API, what makes a PWA installable)

### M0-T08 · `apps/mobile`: Expo SDK 57 app running on your phone
- **Depends on:** M0-T05, M0-T01
- **Read first:** [mobile-android.md §1](../05-system-design/mobile-android.md#1-project-setup)
- **Goal:** a dev build of the Cue app opens on your phone, showing "Cue" and the `SHARED_VERSION` from `@cue/shared`.
- **Steps:**
  1. Create the Expo app (default template with Expo Router) in `apps/mobile` (package `@cue/mobile`).
  2. Follow the Expo monorepo guide so Metro resolves `@cue/shared`.
  3. Set `android.package` in `app.json` to e.g. `app.cue.notes` (choose once; it can't change later).
  4. `npx expo prebuild -p android`, then `npx expo run:android --device` with the phone connected.
  5. Create a release keystore (outside the repo, backed up) and build a release APK once to prove it works.
- **Commands:** `pnpm --filter @cue/mobile exec expo prebuild -p android` · `pnpm --filter @cue/mobile exec expo run:android --device` · `cd apps/mobile/android; .\gradlew.bat assembleRelease`
- **Done when:** the app opens on the phone via the dev build, and a release APK installs on the phone.
- **Docs:** [Expo create project](https://docs.expo.dev/get-started/create-a-project/) · [Expo monorepos](https://docs.expo.dev/guides/monorepos/) · [Development builds](https://docs.expo.dev/develop/development-builds/introduction/) · [Local production build](https://docs.expo.dev/guides/local-app-production/) · [Signed APK](https://reactnative.dev/docs/signed-apk-android)
- **Learning note:** `M0-T08-expo-dev-build.md` (concepts: Expo Go vs dev build, prebuild, Metro bundler, APK signing)
- **Watch out:**
  - **Back up the keystore.** Losing it means you can never update the installed app.
  - If Metro or Gradle can't resolve a package in the pnpm monorepo, add `nodeLinker: hoisted` to `pnpm-workspace.yaml` (Expo monorepo guide), then reinstall.
